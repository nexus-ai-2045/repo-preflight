# ヒットした場所の確認

検査で止まったときは、検出した種類と、修正する場所を端末とJSONに示します。実際のメール・氏名・鍵・ホームの値や、その抜粋を再掲しません。

## フックでの表示

表示例です。ファイル本文なら安全なリポジトリ相対パスと1起点の行番号、名義なら作者・コミッターの欄を示します。

```text
修正箇所: 実ホームパスの形 staged_diff src/settings.py:12
```

- `pre-commit`はステージした差分の追加行を対象にします。表示した行はステージした版の行番号です。作業ファイルをさらに編集している場合、その版とは異なることがあります。
- `commit-msg`はコミットメッセージ内の行を示します。
- `pre-push`は該当コミットの短縮IDと、そのコミットの版の行を示します。
- 名義の指摘は`author.name`・`author.email`・`committer.name`などの欄で示します。許可された名前とメールの組合せを特定できない場合は`author.identity`などの欄になります。
- 非公開設定の禁止パターンに一致した場合は、値の代わりに`deny_patterns[0]`のような設定項目の番号を示します。

普通の日本語ファイル名は、安全に照合できた場合に表示します。ファイル名自体に機微な値がある場合、不明な引用や制御文字がある場合は、その名前を表示しません。

## JSONとスキャン結果

従来の`status`と指摘件数を維持し、不合格の結果に`findings`を追加します。各項目には検出名の`kind`、出所の`source`、安全な`path`、`line`、`commit`、名義欄の`field`、規則・設定番号の`rule`があります。未取得の項目は`null`です。成功したフックのJSONは従来の形式のままです。

スキャンの非公開名義検査でも件数に加えて診断を返します。作業ツリーの個人情報は安全なファイル名、履歴の内容はGitオブジェクトの種類と短縮IDを示します。既存のsecret/path検査が持つ場所も、人向けレポートに表示します。

提供元の検査器が値の一致・不一致だけを返す場合は、「登録済み個人情報に一致」と表示します。具体的な種類や位置を提供していない検査器について、その情報を推測して付け足しません。

## 位置が未確定の場合

複数行や難読化をまとめて調べた結果、バイナリ媒体、gitleaksから位置を取得していない結果などは、正確な行を示せない場合があります。その場合は行を推測せず、未確定と明記します。履歴のblob IDをコミットIDとして表示することもありません。

通常の成功時には診断用の再検査を行いません。不合格時だけ、すでに読んだ差分や本文から場所を探します。診断は最大50項目で、追加の行探索にも文字数・行数の上限があります。`findings_truncated`が正なら打切りや省略があったことを示し、未確定の総件数は表しません。元の不合格判定や指摘件数はこの上限で減らしません。
