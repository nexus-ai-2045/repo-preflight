# 0.12.0 — 保護変更を登録された判断連鎖へ結び付ける

`base-guard`に、設計判断と具体的な差分判断のSSH署名を検証する仕組みを追加しました。対象repository・PR・base branch・操作・保護パス・差分hash・信頼設定hashを結び付け、親の決定文hash、範囲、有効期間、取消を検証します。設計判断だけでは通さず、信頼設定や有効な証拠が無い場合は従来どおり保護変更を停止します。

導入テンプレートは固定された検証器を使い、PRコードを実行せずGit objectとして読みます。信頼設定は最新baseから取得したcommit SHAへ固定し、判定の前後にGitHubの現在のrepo・PR・base・headへ照合します。取得失敗や対象の変化は停止し、古いevent-baseへ戻しません。必須検査、検証を制御するworkflow、承認元設定の変更は、通常の差分承認で免除しません。

同じPRで保護差分と信頼設定が変わらない再実行や、非保護ファイルだけの更新には判断を再利用できます。新しいHEADの通常検査は省略しません。`--decision-request`は未署名の確認対象をJSONで取り出す入口であり、承認・署名・外部送信は行いません。形式と導入境界は[判断連鎖の説明](../human-decision-chain.md)を参照してください。

## 保証する範囲と導入前の判断

署名が示すのは、登録された鍵が決定文へ署名したことです。その場で物理的な人間が操作した証明ではありません。人間の承認元として使う場合は、AIやCIが鍵を自由に使えないことを登録時に確認します。本ツールは本番鍵を生成・探索・読取り・署名せず、署名元を自動登録しません。

既存の利用先への導入と、実際の署名元の選定・登録は未実施です。初回の信頼設定と旧固定版からの移行は、具体的な差分を人が確認してから進めます。現在の形式は単一PRに限定され、別PRへの承認流用や複数PRにまたがる設計権限の委任には対応していません。

ローカルCLIだけではbaseの鮮度を保証しません。チェック完了後のbase変更や取消によって、過去の緑が自動更新される保証もありません。merge直前に最新状態で再検証し、必須チェックの発行主体とbranch保護を別に確認します。検査成功はpush・merge・release・公開の承認ではありません。
