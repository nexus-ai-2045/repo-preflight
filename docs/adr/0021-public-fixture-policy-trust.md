# ADR-0021: 公開ダミー例外の承認元を検査器へ固定する

状態: 採用。2026-10-29。

## 問題

旧形式v1とsecretのみのv2は公開状態の照合を通らず、明示指定された例外を適用していた。v3の内容hashも、検査対象と台帳の両方を変更できる主体の承認を証明しない。

既存の共通CIは検査対象の例外JSONを自動採用しない。この経路は維持し、新しいCIや台帳を追加しない。

## 決定

すべての形式で実際のGitHub repositoryと公開状態を照合する。v1/v2はprivateだけ、v3はpublicだけとし、取得不能・不一致・未知の状態は停止する。取得失敗を機密情報の検出成功とは扱わない。

public v3は実行中の検査器のGit commitに同梱された `.repo-preflight/reviewed-synthetic-fixtures.json` と厳密に解析した内容が一致する場合だけ適用する。検査対象や検査器の未コミットの台帳へ切り替えない。同梱台帳の欠落も停止する。実行する検査器自体は既存のSHA固定と独立レビューで採用する。管理者による検査器・workflowの承認済み変更を防御できるとは主張しない。

既存のrepo・path・内容hash・検出値hash・件数・期限・予約signatureを維持する。件数は既存の復号表現間の集計であり、物理的な出現位置の登録ではない。hash不一致なら例外を適用せず通常検査する。LF/CRLFの既存の同一視も維持する。

新規登録は例外を無効にした同一Git blobの検査、本文と全検出の人間レビュー、台帳登録、検査器の版更新を順に行う。hash一覧やレビュー参照文字列だけを承認証明にしない。publicのsecret規則は除外できず、独立したgitleaksも維持する。既存private例外の用途は拡張しない。

更新したテスト2件に対する既存の形検査例外は、新しい内容へhashを更新しない。元のhashを保持し、固定した旧commitと同じpathの出典を理由欄へ明記する。既存の一覧監査で旧blobとの一致、現在版・別pathへの非適用を確認する。出典を読めなければ失敗とし、ネット取得や検査skipは行わない。これは新しい例外の登録ではなく、旧版のみに対する記録の維持である。

## 後継関係と移行

[ADR-0008](0008-public-synthetic-path-fixtures.md)と[ADR-0017](0017-release-identity-regex-and-fixtures.md)の検出束縛を維持し、任意の外部v3台帳を信頼する部分を本決定で置き換える。利用者側で登録した公開例外は、固定した検査器へレビュー・同梱されるまで適用できない。独立した例外JSONの自動読み込みは追加しない。

## 検証

公開先の旧形式、データと台帳hashの同時変更、自己追加した登録、別path、検出数変更、同梱台帳欠落を拒否する。台帳の未コミット変更では承認内容を変えられない。既存ratchetの実scanで、targetに置いた旧形式台帳がsecretを免除しないことを確認する。保護されたbaseを使う既存base-guardは、台帳とworkflow pinの変更を拒否する。正規の固定ダミー、CRLF、privateの既存用途も対照として確認する。
