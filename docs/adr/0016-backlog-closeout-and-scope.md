# ADR-0016: 滞留PRは必要な検査修正へ統合し、未採用の自動化と分けて閉じる

状態: 採用方針。2026-10-28。独立レビューと必須CIを通した統合PRのマージでmainへ反映する。

## 問題

依存更新PRは、日本語の題名・本文見出しの検査で止まっていた。GIF拡張本文の秘密情報検査とPowerShell文字列回収には未反映の修正がある。一方、免除やリリース時の文書自動更新のドラフトを、この修復のために暗黙採用する必要はない。

## 判断

- #1/#6/#23の依存更新と、#11のGIF拡張検査・検査依存の固定・確認主体の訂正、#32のPowerShell回収とPython回帰修復を、現在のmainへ統合してレビューする。既存のUnicode・差分検査・媒体検査を保持する。
- #25のDependabot本文免除は採用しない。題名の検査は残るため、その免除だけでは依存PRの失敗は解消しない。既存の題名・本文規則を保ち、現在の更新内容を日本語でレビューする。イベント情報から過去の本文編集を完全に証明する追加例外を導入しない。
- #28のリリース時README図自動更新は採用しない。新しい機能・書換え経路であり、検査漏れ修復の前提ではない。コード例を実区画と誤認する未修復の問題もある。将来この機能を明示的に採用するときは、旧PRの内容と指摘から再評価する。
- カナリアの実データと例外の内容hashは維持する。確認主体についての事実と異なる記載だけを訂正し、新しい検査免除を増やさない。

## 閉じ方と保全

統合がマージされるまで、取り込む元PRを完了扱いにしない。元PRの実装と統合差分・検証結果を対応付け、未解決レビューの修復を確認する。未採用のドラフトは「実装済み」とせず、不採用理由と再開先を記録して閉じる。

枝は、先端hash・PRの状態・後続への移送・作業ツリー内の未コミット差分を照合する。現mainへ取り込まない旧履歴や未採用案は、PR参照と復元可能なローカル保全を確認してから枝を整理する。資料や他担当の未反映内容を削除しない。

## 保証境界

CI必須検査、秘密情報検査、公開範囲、hook・認証・時間ベースの自動化の設定は緩めない。PRを閉じたことだけで変更が反映済みとは扱わない。ローカル検証とGitHub CIの成功は分ける。
