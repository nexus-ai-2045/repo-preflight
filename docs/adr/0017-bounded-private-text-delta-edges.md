# ADR-0017: 非公開本文の差分比較前に厳密一致する両端を確定する

状態: Proposed。2026-10-29。ローカル実装候補であり、独立レビュー・採用と本線反映は別途行う。

## 問題

大きな既存台帳に安全な数行を追加しただけでも、旧本文と新本文の行数積が予算を超えると、差分検査が新本文の全文検査へ戻る。既存の検出が新しい送信差分の阻害要因となり、追加箇所と検出の帰属を区別できなくなる。

## 判断

既存の非公開本文差分入口 `private_text_delta_views` で、行のバイト相当の厳密な文字列一致により最大の共通prefixと重ならないsuffixを先に確定する。残るmiddleの行数積に既存の比較予算を適用し、既存のSequenceMatcherへ渡す。確定した両端とmiddleの操作範囲を全文offsetへ戻す。

全文の静的文字列解析、正規表現の役割と束縛、候補の出典、sourceの全出現箇所に対する既存の不変確認は維持する。変更行だけを検査する方式にはしない。文字数の全文上限と、確定できないmiddleに対する従来の全文fallbackは維持する。

反復するsourceは、その値が以前にあっただけでは免除しない。新本文のいずれかの出現が変更範囲にかかる場合は再検査する。既存prefixに新pieceを足す復元、同じ値の別出典での生成、束縛削除による役割変化を拒否する。

## 検証と限界

既存の正常系・新規private値・復元・役割束縛のテストを維持し、大きな本文、曖昧な重複、両端の非重複、middle予算超過の回帰を加える。秘密情報の検査入口には変更を加えない。新規pathやsecretの拒否は既存scannerの回帰でも確認する。

閾値を引き上げない。fallbackの検出を捨てない。判定不能は既存どおり閉じる。すべての大きな変更が差分判定可能になる保証ではない。外部公開・送信・hook・認証・リリースの境界は変更しない。
